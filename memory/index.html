Project memory

Your agents learn. Your project remembers.

Every new session shouldn’t mean starting over.

KodaCode builds lasting project knowledge from what your agents discover: how to build and test your code, which fixes worked, why architectural decisions were made, and the conventions your team follows. Before each turn, it retrieves the memories relevant to the task, giving your agents the context they need without making them relearn the project.

Nothing is buried in a black box.

Explore memories as a list, graph, or timeline. Correct mistakes, connect related knowledge, remove outdated information, and trace every change through its history.

Knowledge that travels with your code.

Commit project memory alongside your source code so teammates can share discoveries, preserve decisions, and give every agent the benefit of lessons learned across the team.

The longer you use KodaCode, the more your project’s knowledge compounds.

01What you can do · With memory
Ask in plain words

Ask the agent "why do webhooks fail in staging?" and it recalls the problem, its cause and the fix, together.

See how it connects

Browse memories as a list, as a graph of what solves and causes what, or as a timeline of when each was learned.

Edit anything

Change a title or its content, retag it, or raise its importance so it comes up first.

Link it yourself

Join two memories with the relationship that explains them: solves, causes, builds on, replaced by and more.

Keep the history

Every change to a memory is kept, so you can see what it said before and who changed it.

Take it anywhere

Export to Markdown or JSON, or import a memory you've exported before.

02Fewer tokens · Learned once

It doesn't have to figure it out twice.

Without memory, every session starts from scratch, and the agent spends time and money relearning things, like why a test is flaky, which command replays a webhook, or why a setting has the value it does. With memory, it looks the answer up, along with the reason, and gets on with the work.

03For teams · Shared memory

Keep it to yourself, or share it with the team.

Memory stays on your computer unless you point the project at a shared file. Commit that file and everyone's KodaCode reads and adds to it, so a fix one person found is something every agent on the team already knows.
