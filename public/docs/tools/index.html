Agent tools

The tools the agent can call, what each one does, and how it shows in the transcript.

#Files and code

ToolWhat it does
query_code_graphReturns the source of the symbols that a question is about, and the call path between them. Also answers schema questions. The agent's first stop. See Code graph.
read_fileReads a file from the workspace or from a directory that you added, 100 lines at a time by default. Also lists directories.
write_fileWrites a file's whole text, creating or replacing it.
edit_fileReplaces exact text in a file. Several edits to one file apply together or not at all.
retrieveReturns the full content of an older result that was shortened.

#Commands

ToolWhat it does
shellRuns a command and returns its output, or a session id when it's still running after yield_time_ms. See Commands & the terminal.
write_stdinPolls a running command, types into it, or sends Ctrl-C.

#Web

ToolWhat it does
web_searchSearches the public web. Returns source URLs, highlights and dates.
web_fetchFetches one public page by URL as Markdown.

#Planning and asking

ToolWhat it does
ask_userAsks you one to three questions, each with two to four options. You can type your own answer.
enter_plan_modeSwitches the session to plan mode.
propose_planHands you a plan and waits for your verdict.
update_planReports progress on an accepted plan's steps.
update_goalSays the goal this session runs has ended: complete, or blocked.
goal_statusReads the progress of this project's goals.

#Agents and background work

ToolWhat it does
taskHands a task to an agent, isolated or with the conversation so far.
close_agentCloses a subagent and stops its running commands.
check_taskWaits for a background task an MCP tool started.
cancel_taskStops a background task an MCP tool started.

#Memory, sessions and skills

ToolWhat it does
memoryStores, recalls, links and searches memories.
search_sessionsSearches or reads this project's earlier sessions.
read_skillReads a skill's instructions or a file bundled with it.

MCP servers add their own tools under their own names.

#Crew tools

During a crew, the leader, the manager and the workers get their own tools:

ToolUsed byWhat it does
taskSupervised leaderSends one change to a worker as a checked task, with done_when, retry_of or steps.
researchSupervised leaderAsks a read-only worker a question about the code. The answer gives file:line references.
crew_statusSupervised leaderLists, shows or stops the jobs of this conversation.
crew_changesSupervised leaderDiscards a job that waits for a decision. Only you can apply one.
crew_decideSelf-managed managerRecords the plan, edits the task list, and picks the next task or ends the run.
reproduceSupervised workerRuns the test that reproduces the problem before the fix.
finishWorkersReports the work as done. A Self-managed worker also gives the command that runs its test.
