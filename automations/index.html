01How it decides · Decision models

A cheap model does the checking.

Running a full agent every few minutes would be slow and expensive. So each check goes to a small model whose only job is to answer your questions (yes or no, pick one, or a score) and say how sure it is. Run it on your own machine through Ollama, through OpenRouter, or on your own server, with models like nimble or Jev. The big agent only starts when one of your rules says so.

02What you can automate · A few ideas
Infrastructure

Read a status export or a config every couple of hours, and wake an agent when disk, certificates or capacity need attention.

Releases

Every weekday evening, read everything since the last tag, decide whether any of it matters to users, and get release notes drafted.

Dependencies

When a commit adds a package, check its licence, how well it's maintained, and whether you already have one that does the job.

Security

Catch a key, token or password in the latest commit, and plan how to remove it from history and rotate it.

Tests and data

Notice changed functions no test reaches, or a migration that drops a column the code still uses.

Anything else

If a file or a read-only command can show it, an automation can keep an eye on it.

03As many as you want · Yours or the team's

Six come built in, and you can add your own.

Save an automation in the project and your whole team gets it with the code. Keep it to yourself and run it in every project, a few of them, or none at all. Before you save, Try it runs the check once and shows you what would happen, without actually doing it.
