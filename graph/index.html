The code graph

See how your code connects.

Your agents shouldn’t have to read your codebase to understand it.

KodaCode keeps a live map of your project: every file, every function, and what calls what. Instead of searching and opening file after file, agents ask the map and get the answer directly.

More focus, fewer tokens.

Context goes to your task, not to code the agent didn’t need. Sessions run longer before compacting, and you pay for less.

A map you can explore too.

Open the same graph yourself and trace how your code fits together, from a single function to the whole project.

Less searching. More understanding.

01What you can do · With the map
Take in the whole project

Files grouped by folder, with the links between them drawn. Hide a folder to cut the noise.

Focus on what changed

Switch to changed files and see only what you touched, plus everything that depends on it.

Ask who calls this

Pick a function to see its callers and the functions it calls, each marked certain or likely.

Retrace your steps

Every jump you make is kept as a path, so you can walk back to where you started.

Read the database too

Tables, columns and indexes from your SQL migrations or your ORM, each listed with the code that names it. Works with Prisma, Drizzle, TypeORM, Sequelize, Knex, Django, SQLAlchemy, Rails, Diesel, GORM and Entity Framework.

Jump to the source

Open any file or function in the editor, at the line it starts on.

02Why it matters · For agents

The agents use it too.

When an agent asks the map who calls a function, it gets back the callers and their signatures instead of whole files. So it reads less, guesses less and costs less to run. The same map lets automations spot a changed function that no test covers, or a deleted column the code still uses.
