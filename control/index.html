Control

Your workflow. Your rules. Your control.

Autonomy is a dial, not a switch.

Set the rules for each project and decide how much your agents can do on their own. On your machine, KodaCode asks before it edits a file or reaches outside the project.

Hands-off where it’s safe.

In a container, let agents work straight through, or have every change wait for your approval.

Boundaries that hold.

Commands that touch paths outside the project, rewrite git history or change the system ask first, and network access is yours to allow.

As much freedom as you’re comfortable with, and not one step more.

01When it stops for you

It asks before changing things, not before reading them.

With "Ask before each" on, every edit waits for you to accept or reject it, and you can add a note for the agent. The same goes for any command that adds, edits, deletes or downloads files in the project, whatever the agent calls it. Builds, tests and installs never ask. Commands that touch anything outside the project, rewrite git history or change your system ask first too.

Run onceLets this one command run, and asks again next time
Allow for this sessionStops asking for that command, the places it named, or that kind of change, until the app closes
DenyNothing runs, and the agent is told not to try it another way
A noteSay why, or what to do instead, and the agent reads it
02Sensible defaults
On your machineAsks before each change inside the project, and before any command that reaches outside it
In a containerApplies changes directly and lets commands run, because the container holds only the project and the folders you share · isolation
Per projectEach one is a switch in the project's settings, so a scratch repo and your production service can behave differently
03Safety nets
UndoEvery run is recorded before it starts. One click puts it back
Keep or discardChanged files are listed with their lines added and removed, each with its own Keep and Discard
Plan modeThe agent reads and proposes, and nothing is written until you accept the plan
GoalsWork in their own copy of the project and stay inside it unless you allow otherwise
Your keysAPI keys and sign-in tokens live in your system's keychain, never in a plain-text file or an environment variable
